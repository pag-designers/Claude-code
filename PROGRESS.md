## CP5 — what was built (BRIEF §9 + the CP5 line of §11, ADR-021 / ADR-022)

- **Accounts:** Settings → Integrations has, per platform, a step-by-step guide for creating YOUR OWN developer app, secret inputs, the exact redirect URI to register (copy button) and **Connect** (system browser, loopback redirect, PKCE + state, 5-minute timeout, Cancel). Connected accounts show status, **Test connection**, **Disconnect** (its scheduled posts become drafts) and **Reconnect**. Tokens are encrypted in `tokens.bin` (same cipher as the secrets) and never leave the main process.
- **Publishers (official APIs only):** YouTube Shorts (`videos.insert` resumable upload with resume after a dropped connection), Instagram Reels (Instagram Login flow, container → poll → publish, Instagram pulls the video from a presigned storage URL, first comment), TikTok (Direct Post or upload-to-drafts, chunked upload, rotating refresh tokens, creator privacy options, unaudited-app downgrade with a note). Errors are mapped to auth / rate-limit / quota / validation / media / network / platform with the platform's own words + a hint.
- **Scheduler page** (`/scheduler/`): month/week/day calendar (drag to reschedule), queue with needs-attention / upcoming / drafts / history, filters, post drawer (per-platform fields with live counters, media report + Auto-fix, Post now / Cancel / Retry / Delete, result link + stats, platform error + hint), account strip with quota meters, status bar (active / paused, next post, catch-up). **Schedule dialog** from Library (clip drawer "Post…", selection bar "Schedule…", Exported card, editor "Export & Schedule"): multi-account, one tab per platform prefilled from the CP2 metadata + default Brand Kit hashtag sets, mandatory YouTube "made for kids", TikTok unaudited banner, Post now / Pick a time / **Smart spacing** with an editable preview.
- **Reliability:** durable `posts.publish` jobs; scheduler tick loop with pause; **catch-up on launch** (late within the grace window → published, older → "missed — reschedule?"); backoff/retry policy (`decideRetry`); quota pre-check and per-day usage; media validation against sourced platform limits and **one-pass auto-fix** (never crops/trims); **tray / menu bar** mode (close hides the window while posts are pending) with a quit confirmation; daily digest notification; top-bar "Scheduler active · next …" chip; notification deep links `/scheduler/?post=<id>`.
- **Plumbing:** migration 0006 (`SocialAccount`, `Post`, `QuotaUsage`), 19 new IPC channels + 3 events, `shared/{publish,scheduling,platform-specs}.ts`, 7 dev/test base-URL switches, three fake provider servers for tests, **ADR-022: one SQLite build per process** (fixes random "disk I/O error" / "malformed" found by the restart e2e).

## CP5 — NOT verified / known issues (read this)

- **Nothing was run against real YouTube, Instagram or TikTok.** There are no developer apps here. The three fake servers were written from the official docs (read 2026-10-15 through a page summariser, not raw pages) and enforce what the real ones are documented to enforce; the real wire formats, error codes and review rules may differ.
- **Instagram redirect URI:** Meta's "Valid OAuth redirect URIs" may require https and refuse `http://127.0.0.1:<port>`. Unconfirmed. If it does, Instagram Connect needs a local certificate or a Facebook-Login variant (not built). Also unconfirmed: that Development mode needs no App Review for your own account; the Instagram publish limit is documented as both 50 and 100 per 24 h; `access_token` as a form field and the `collaborators` format.
- **YouTube:** the docs now describe `videos.insert` as 100 uploads/day (own bucket, 1 unit); BRIEF §9 and older guides say ~1,600 of 10,000 units. The app follows the current page. Google may keep uploads of a NEW, unverified API project private until a compliance audit: that would break "a real Short lands on the channel" until the audit passes (the Settings explainer says so, hedged). Consent screen left in "Testing" makes refresh tokens expire after 7 days (the guide says to publish it).
- **TikTok:** an unaudited app can only post privately and the posting account must itself be private; public posting needs TikTok's audit (a checklist is in Settings, the audit itself is outside the code). Drafts take no caption (the user adds it in TikTok). The hex PKCE challenge and the loopback-redirect rule are from the docs only. `url` of a TikTok post is built by convention.
- **Instagram duplicate risk:** if the connection drops exactly during `media_publish`, a retry can create a second Reel (Instagram has no container→media lookup).
- **Tray / menu bar, hide-on-close and the quit prompt were never run on macOS or Windows** (Linux xvfb has no tray; only the controller logic is unit-tested). macOS template icons are unchecked. On Linux without a status-notifier host the window close still quits.
- Hardware encoders (nvenc/VideoToolbox) for the auto-fix were not run (libx264 only); HDR/10-bit sources are converted to 8-bit without tone mapping; ffprobe 4.0.2 cannot read H.264 interlacing.
- Stats refresh (views/likes) is only exercised against the fakes; TikTok returns none.
- "Local API (bonus)" from BRIEF §9 is not built (candidate for CP8). The serverless-worker interface is described in ADR-021 only.
- Rescheduling is by drag; the keyboard path is the date picker in the post drawer. Remote avatar URLs were tested with data URIs only.
- **Database I/O fault on the user's Mac (open):** after pulling CP5 the user's log still showed `queue tick failed: DriverAdapterError: disk I/O error` on every poll (the start of the log was not seen: it is unknown whether the ADR-022 build was running). Added self-healing (reconnect, throttled log, ADR-022 addendum); the root cause on macOS is unconfirmed. Next step if it persists: the first error lines of `main.log`, `ls -la` of the app-data folder, and whether a second Clipfern instance (menu bar) is running.
- Carried over: real Claude quality unverified; audio never listened to; 60 fps on a real GPU unmeasured; macOS/Windows not run; the user's macOS Settings "disk I/O error" is plausibly fixed by ADR-022 but NOT confirmed on their machine (and their yt-dlp Diagnostics "Problem" is addressed but unconfirmed). CP4 known issues above still apply.

## CP1 — what was built

- **Pipeline** (`electron/main/pipeline/`): durable-queue job per video + one per clip render. Stages: ingest → prepare (audio, 480p proxy, shot detection) → transcribe + moments (10-min windows, ranked while the next window transcribes, strong clips render immediately) → understand (overview, chapters, notes, topics) → select (top N / ≥ minScore) → render → finalize (upload proxy, free local disk). Resumes after restart; per-stage retry; cancel; cross-run transcript cache in object storage; clips ≥ 72 start rendering as soon as they are found.
- **Services:** yt-dlp ingest with client fallback + actionable bot-check error; ffmpeg media; audio signals (loudness, speech rate, silences, laughter/applause, speaker changes) + sentence segmentation; Claude layer (structured outputs, sentence-id spans, prompt caching, budget guard, cost recording, repair retry); multi-signal candidate generator + word-boundary snapping; face-tracked smooth crop path (EMA/dead-zone, cut-aware); "Clean Pop" ASS captions (word-level, active-word pop, safe area, Montserrat ExtraBold shipped) + hook title card + SRT/VTT; FFmpeg render (sendcmd crop pan, burn captions, −14 LUFS two-step loudnorm, hardware-encoder probe by test encode, 1080×1920 H.264/AAC).
- **UI:** real Home flow (URL validation, probe preview with CC badge, options, readiness blockers), live pipeline view (7 stages, ETA, log, retry/cancel), Library (Videos / Clips / Favorites; filters, sort, grid/list, hover preview, multi-select, bulk download/favorite/delete), video detail (Overview / Transcript with search + seek / Chapters / Clips / Notes), clip drawer (player, score breakdown bars, source jump, download/re-render), live AI-cost chip.
- **IPC:** 17 new channels + 3 events (see `shared/ipc.ts`); schema migration 0002 (non-destructive ADD COLUMNs).

### Bugs found by running it for real (all fixed, with regression tests)

1. Sidecar HTTP client died on any request > 5 s (Node's default agent idle timeout) — real transcription could never finish. Dedicated agent; test fails without the fix.
2. `pipeline:start` options patch re-applied zod defaults (same class as the CP0 settings bug) → `pipelineOptionsPatchSchema`.
3. `settings:set`/`secrets:*` refreshed the storage provider fire-and-forget → an immediate Start saw stale state; handlers now await it.
4. Orchestrator hinted candidates from the overlap context region (belonging to the previous window) → wasted ranking slots; now only the new region, +2 spare picks on later windows. Skip reasons are logged.
5. Cost: Haiku 5.5 long-prompt tier (> 100K tokens bills 5×) added to pricing.
